# System-Managed Resources Container

**Last Verified:** 2026-08-31


**Version**: 1.0.0  
**Created**: 2026-01-14  
**Status**: Active  
**Purpose**: Define container for system-managed resources that should be ignored by git, with snapshot support for non-reconstructible state

## Overview

System-managed resources are files and directories that are:
- Generated by the system during operation
- Can be regenerated from source data (in most cases)
- Should not be committed to version control
- May need snapshots for developer onboarding

## Container Structure

```
.zqk/
├── system-state/              # System-managed resources container
│   ├── cas-indices/           # CAS index files (ID -> hash mappings)
│   │   └── {kind}/.{kind}.index
│   ├── snapshots/             # Snapshots of critical state
│   │   ├── cas-indices/       # CAS index snapshots
│   │   │   └── {timestamp}-cas-indices.tar.gz
│   │   └── metadata/          # Snapshot metadata
│   │       └── {timestamp}-snapshot.json
│   └── README.md              # Explains what's here and how to restore
├── cache/                     # Runtime caches (already ignored)
├── logs/                      # Log files (already ignored)
└── ...
```

## Resource Categories

### 1. CAS Index Files (Reconstructible)

**Location**: `docs/process/{kind}/.{kind}.index` (current) or `.zqk/system-state/cas-indices/{kind}/.{kind}.index` (future)

**Purpose**: Maps object IDs to content hashes for CAS-enabled kinds

**Reconstructibility**: ✅ **Fully reconstructible**
- Can be rebuilt by scanning hash files in `docs/process/{kind}/`
- Can be regenerated via `zqk system rebuild-cas-indices`

**Git Status**: Ignored (already in `.gitignore`)

**Snapshot Strategy**: Optional - can be included in snapshots for faster onboarding, but not required

### 2. Lock Files (Temporary)

**Location**: `docs/process/**/*.lock`, `.zqk/**/*.lock`

**Purpose**: Temporary file locks for concurrent access control

**Reconstructibility**: ✅ **Not needed** - temporary, auto-cleaned

**Git Status**: Ignored

**Snapshot Strategy**: Not needed

### 3. Cache Files (Runtime)

**Location**: `.zqk/cache/`

**Purpose**: Runtime caches (validation cache, object ID cache, etc.)

**Reconstructibility**: ✅ **Fully reconstructible**
- Validation cache: Rebuilt on first validation run
- Object ID cache: Rebuilt via `zqk system check --refresh-cache`

**Git Status**: Ignored (already in `.gitignore`)

**Snapshot Strategy**: Not needed - caches are performance optimizations

### 4. Metrics Files (System-Generated)

**Location**: `docs/process/metrics/`

**Purpose**: System-generated metrics (scheduler health, file lock metrics, etc.)

**Reconstructibility**: ✅ **Not needed** - historical data, can start fresh

**Git Status**: Ignored (already in `.gitignore`)

**Snapshot Strategy**: Not needed

### 5. Audit Events & Change Journal (System-Generated)

**Location**: `docs/process/audit/`, `docs/process/change_journal/`

**Purpose**: Historical audit trail and change tracking

**Reconstructibility**: ✅ **Not needed** - historical data, can start fresh

**Git Status**: Ignored (already in `.gitignore`)

**Snapshot Strategy**: Not needed

## Snapshot Strategy

### What Needs Snapshots?

**Critical State** (cannot be easily reconstructed):
- **CAS Index Files**: While reconstructible, rebuilding can be slow for large repositories
  - **Snapshot**: Include CAS indices in snapshots for faster onboarding
  - **Restore**: `zqk system restore-snapshot {snapshot-file}`

**Non-Critical State** (can be reconstructed or not needed):
- Lock files: Temporary, not needed
- Cache files: Performance optimization, can be rebuilt
- Metrics: Historical data, can start fresh
- Audit events: Historical data, can start fresh

### Snapshot Format

```json
{
  "version": "1.0.0",
  "created_at": "2026-01-14T13:30:00Z",
  "created_by": "zqk system snapshot",
  "description": "CAS indices snapshot for developer onboarding",
  "contents": {
    "cas_indices": {
      "count": 35,
      "kinds": ["backlog_item", "criteria", "test_case", ...],
      "archive": "cas-indices-20260114-133000.tar.gz"
    }
  },
  "restore_instructions": "Run: zqk system restore-snapshot cas-indices-20260114-133000.tar.gz"
}
```

## Commands

### Create Snapshot
```bash
# Create snapshot of CAS indices
zqk system snapshot --cas-indices --output .zqk/system-state/snapshots/

# Create full system state snapshot
zqk system snapshot --all --output .zqk/system-state/snapshots/
```

### Restore Snapshot
```bash
# Restore CAS indices from snapshot
zqk system restore-snapshot .zqk/system-state/snapshots/cas-indices-20260114-133000.tar.gz

# Restore with validation
zqk system restore-snapshot --validate .zqk/system-state/snapshots/cas-indices-20260114-133000.tar.gz
```

### Rebuild State (Alternative to Restore)
```bash
# Rebuild CAS indices from hash files
zqk system rebuild-cas-indices

# Rebuild object ID cache
zqk system check --refresh-cache
```

## Benefits

1. **Clean Git Repository**: System-managed files don't clutter git history
2. **Fast Developer Onboarding**: Snapshots provide pre-built state
3. **Flexibility**: Developers can rebuild from scratch or use snapshots
4. **Transparency**: Clear separation between source data and system state
5. **Recovery**: Snapshots provide backup of critical state
