# Architecture Lifecycle Reminders

**Last Verified:** 2026-08-31


**Version**: 1.0.0  
**Created**: 2025-01-02  
**Status**: Active  
**Purpose**: Integration of architecture compliance into the lifecycle reminder system

## Overview

The lifecycle reminder system (see [BLI-092](../../backlog/BLI-092.yaml)) can provide timely, proactive reminders about architecture compliance throughout the project lifecycle. This document describes how architecture reminders work and how to configure them.

## Architecture Reminder Types

### 1. Pattern Violation Reminders

**Trigger**: Code violates established architecture patterns

**Example**:
```
⚠️  Architecture Reminder: Pattern Violation
   Object: pkg/mcp/metrics_bridge.go
   Issue: Duplicate bridge pattern detected
   Suggestion: Use CLI bridge pattern instead
   Pattern: docs/process/architecture/mcp-cli-bridge-v1.0.md
   Severity: high
   Reason Code: architecture
```

### 2. Missing ADR Reminders

**Trigger**: Significant architectural change lacks ADR

**Example**:
```
⚠️  Architecture Reminder: Missing ADR
   Context: New package pkg/mcp/bridge created
   Issue: No ADR documents this architectural decision
   Suggestion: Create ADR-XXX documenting bridge pattern decision
   Severity: medium
   Reason Code: architecture
```

### 3. Import Cycle Reminders

**Trigger**: Import cycle detected in codebase

**Example**:
```
❌ Architecture Reminder: Import Cycle Detected
   Cycle: pkg/mcp → pkg/metrics → pkg/storage → pkg/mcp
   Issue: Circular dependency violates architecture
   Suggestion: Refactor to use interfaces or bridge pattern
   Severity: critical
   Reason Code: architecture
```

### 4. Abstraction Violation Reminders

**Trigger**: Code violates storage/provider abstraction

**Example**:
```
⚠️  Architecture Reminder: Abstraction Violation
   File: pkg/mcp/server.go
   Issue: Direct import of storage.FileObjectStorage
   Suggestion: Use storage.ObjectStorageProvider interface
   Pattern: docs/process/architecture/object-storage-provider-v1.0.md
   Severity: high
   Reason Code: architecture
```

### 5. Stale Pattern Reminders

**Trigger**: Architecture patterns haven't been reviewed recently

**Example**:
```
ℹ️  Architecture Reminder: Stale Pattern
   Pattern: docs/process/architecture/mcp-cli-bridge-v1.0.md
   Issue: Pattern hasn't been reviewed in 6 months
   Suggestion: Review and update pattern documentation
   Severity: low
   Reason Code: architecture
```

## Configuration

### Reminder Thresholds

Configure staleness thresholds for architecture reminders:

```yaml
# .zqk/config.yaml
architecture:
  reminders:
    enabled: true
    check_interval: daily
    thresholds:
      pattern_violation: immediate
      missing_adr: 7 days
      import_cycle: immediate
      abstraction_violation: immediate
      stale_pattern: 180 days
    severity_levels:
      pattern_violation: high
      missing_adr: medium
      import_cycle: critical
      abstraction_violation: high
      stale_pattern: low
```

### Reminder Channels

Configure how reminders are delivered:

```yaml
architecture:
  reminders:
    channels:
      - cli        # Show in CLI commands
      - mcp        # Available via MCP tools
      - lifecycle  # Integrated with lifecycle system
    filters:
      include_low_priority: false
      cooldown_days: 7
```

## Usage

### CLI Commands

```bash
# Get all architecture reminders
zqk lifecycle reminders --reason-code architecture

# Get high-severity architecture reminders only
zqk lifecycle reminders --reason-code architecture --severity high

# Get reminders for specific object
zqk lifecycle reminders --reason-code architecture --object pkg/mcp
```

### MCP Integration

```json
{
  "name": "get_lifecycle_reminders",
  "arguments": {
    "reason_code": "architecture",
    "severity": "high",
    "include_low_priority": false
  }
}
```

### Lifecycle Evaluation

Architecture reminders are automatically generated during lifecycle evaluation:

```bash
# Lifecycle evaluation includes architecture checks
zqk lifecycle evaluate --include-architecture

# Evaluate specific object with architecture checks
zqk lifecycle evaluate pkg/mcp --include-architecture
```

## Implementation

### Reminder Generation

Architecture reminders are generated by:

1. **Pattern Checker**: Scans code for pattern violations
2. **ADR Checker**: Verifies ADRs exist for architectural changes
3. **Import Cycle Detector**: Detects circular dependencies
4. **Abstraction Checker**: Validates abstraction layer compliance
5. **Pattern Staleness Checker**: Monitors pattern review dates

### Integration Points

1. **Lifecycle Evaluation**: Architecture checks run during lifecycle evaluation
2. **Object Status Changes**: Checks trigger on object status changes
3. **Periodic Audits**: Scheduled checks for ongoing compliance
4. **Pre-Commit Hooks**: Immediate feedback (existing)
5. **CI/CD Pipeline**: Blocking checks in pipeline

## Reminder Lifecycle

### 1. Detection

Reminders are detected by:
- Static code analysis
- Build-time checks
- Runtime validation
- Periodic audits

### 2. Generation

Reminders are generated with:
- Object reference
- Issue description
- Suggested action
- Related patterns/ADRs
- Severity level

### 3. Delivery

Reminders are delivered via:
- CLI commands
- MCP tools
- Lifecycle evaluation
- Periodic reports

### 4. Resolution

Reminders are resolved when:
- Issue is fixed
- ADR is created
- Pattern is updated
- Violation is addressed

### 5. Tracking

Reminder history is tracked:
- When reminder was created
- When reminder was resolved
- Resolution action taken
- Time to resolution

## Benefits

1. **Proactive**: Reminders surface before issues become critical
2. **Contextual**: Reminders include relevant patterns and ADRs
3. **Actionable**: Clear suggestions for resolution
4. **Integrated**: Works with existing lifecycle system
5. **Configurable**: Thresholds and channels configurable
