## Highlights & Strategic Capabilities

The `v0.3.8` release focuses on **Greenfield Onboarding Polish & Zero-Friction First-Run Reliability**, resolving four high-impact community onboarding regressions discovered during fresh project dogfooding so that every new repository initialized with `zqk init` starts with zero Tier 1 blockers, zero policy warnings, valid strategic object defaults, and strict project-local binary isolation across IDE MCP integrations:

### 1. Zero-Blocker Greenfield Bootstrap & Default Persona Skill Integrity (`scripts/default_personas/technical_program_manager.yaml`, `pkg/bootstrap/archive/bootstrap.tar.gz`)
- **Valid Community Skill Binding on `PER-COMMUNITY-TPM`**: Replaced the unseeded `ASK-COMMUNITY-TPM-ORCHESTRATION` reference in the community bootstrap persona template with seeded community skills (`ASK-COMMUNITY-ZQK-EXPERT`, `ASK-COMMUNITY-OBJECT-STEWARD`, `ASK-DEFAULT-FEED-CORRESPONDENCE`).
- **Immediate `zqk system check` Pass After `zqk init`**: Rebuilt the embedded community bootstrap archive with verified seed impermeability so fresh projects pass `zqk system check` with zero Tier 1 `GhostRef` blockers out of the box.

### 2. Strategic Object Materialization Ergonomics (`cmd/zqk/new/new.go`)
- **Dedicated Narrative & Mission Statement Flags**: Added `--narrative` (for `zqk new vision` / `zqk new object vision`) and `--mission-statement` (for `zqk new mission` / `zqk new object mission`).
- **Automatic Fallback for Direct `--cas` Materialization**: When `--cas` is used without explicit statement flags, `zqk new vision` and `zqk new mission` automatically populate `narrative` and `mission_statement` from `--description`/`--content` (falling back to `--title`), eliminating immediate Tier 1 validation failures on newly minted strategic objects.

### 3. Starter Onboarding Decommission & `POL-DOC-001` Compliance (`cmd/zqk/system/init_progress.go`, `cmd/zqk/system/init_starter_graph.go`)
- **Copy-Paste Decommission Guarantee Banner**: Updated the post-`zqk init` Decommission Guarantee output to include a valid `--reason-code` (`>= 30` characters), matching the break-glass delete contract for core `priority_plan` objects.
- **Zero-Warning Starter Requirement**: Aligned `CRIT-STARTER-COMMUNITY-001` with `POL-DOC-001` documentation compliance so both fresh `zqk init` runs and post-decommission checks exit cleanly with zero warnings.

### 4. Project-Local MCP Binary Isolation (`pkg/mcp/install.go`)
- **Hermetic Executable Resolution (`resolveMCPServerCommand`)**: When `zqk init` or `zqk mcp install` runs from a project-local installation (such as `install.sh --prefix=<project>/bin`) or a binary that does not match the first `zqk` on `$PATH`, generated `.claude.json` and workspace MCP configurations now record the resolved project-local executable path instead of bare `"zqk"`, preventing silent host `$PATH` binary leakage.

## Upgrade Guide

- **Backwards Compatibility**: Fully backwards compatible with existing `.zqk/process` repositories, schemas, and `v0.3.7` workspaces.
- **Upgrade Command (Homebrew)**:
  ```bash
  brew upgrade zqk-os/tap/zqk
  ```
- **Upgrade Command (Direct Domain)**:
  ```bash
  curl -fsSL https://zqk.dev/install.sh | bash
  ```
- **Fallback GitHub Raw Mirror**:
  ```bash
  curl -fsSL https://raw.githubusercontent.com/zqk-os/zqk/main/scripts/install.sh | bash
  ```
- **Post-Upgrade Verification**:
  ```bash
  zqk system check --refresh-cache
  zqk workflow whats-next
  ```
